# AI usage disclosure

I used AI extensively while completing this task.

My main technical focus before this assessment was cybersecurity, particularly SOC and Blue Team work. I had also been interested in DevOps and wanted to explore it as a possible career direction, but I did not previously have much hands-on experience with Docker Compose, NGINX, CI/CD, infrastructure troubleshooting, and failure testing. I therefore treated this assessment as an opportunity to learn DevOps while solving the actual task.

I used ChatGPT (GPT-5.6 Luna) extensively as a learning and troubleshooting assistant throughout the work. I used it to understand unfamiliar DevOps concepts and commands, interpret terminal output, troubleshoot problems, review configuration, and understand why particular changes were needed.

* **Tool/model:** ChatGPT (GPT-5.6 Luna)
* **Purpose:** Learn DevOps concepts, understand Docker and Docker Compose, understand NGINX routing and networking, troubleshoot the supplied environment, work through validation and failure testing, understand CI and persistence, and structure the required documentation.
* **AI usage level:** AI was used extensively because DevOps was a learning area for me during this assessment. My primary background and focus was cybersecurity, so I relied on AI to help me learn unfamiliar DevOps concepts while applying them to the real environment.
* **Files and areas affected:** `Dockerfile`, `docker-compose.yml`, `nginx/nginx.conf`, `validate.py`, `failure_test.py`, `backup.sh`, `restore.sh`, `.github/workflows/ci.yml`, and the documentation files.
* **How AI was used:** I asked AI to explain concepts, interpret real terminal output, suggest commands, review configuration, help identify causes of failures, and help structure documentation and testing.
* **How I verified the work:** I ran the commands myself in the actual assessment environment and checked the resulting Docker Compose state, container health, network membership, port exposure, HTTP responses, load balancing, failure recovery, database persistence, backup/restore behavior, validation results, Git changes, and CI results.
* **What I changed or rejected:** AI suggestions were not accepted automatically. I compared them with the actual environment and task requirements and changed or rejected suggestions when they did not match what I observed.
* **Understanding and ownership:** Although I used AI heavily while learning DevOps, I made sure I understood the commands and configuration changes I applied. I verified the behavior myself and only kept results that I could reproduce in the actual environment.
* **Evidence integrity:** I did not use AI to fabricate test results, commit dates, timestamps, challenge receipts, CI results, or other evidence. Where a test or recording was incomplete, I documented that limitation rather than presenting it as successful.

This assessment was therefore both a technical task and a learning opportunity. My main background is cybersecurity, and the task gave me practical exposure to DevOps concepts that I wanted to learn and potentially pursue further.

AI assistance is disclosed here because it materially contributed to my learning, troubleshooting, implementation guidance, and documentation.
